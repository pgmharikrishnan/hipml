# WP52: the split-K ffn scratch crash at prefill tails

Base: `a9bf6d2` (`feat/release` with review4 and WP48). Branch
`feat/splitk-fix`. Box: R9700 (gfx1201, 32 GB), Qwen3.8-27B Q4_K_M, q8 KV.
All GPU work ran under the `wp52` lock, port 8093 only.

## 1. The failure

`hipml generate` on a prompt whose last chunk is short exits 1:

```
generate: chunked prefill: prefill_q4_k_w2h_sk: split scratch has 1 values, needs 17408
```

`HIPML_SPLITK=0` works (8,193-token prefill 6.7 s). No fixture or bench cell
hit it because every fixture length is either shorter than the chunk or a
clean multiple of it.

### Which lengths crash

Reproduced on `a9bf6d2` with the default 2,048-token chunk. The crash set is
exactly `2048*k + r` for `k >= 1` and `1 <= r <= 1024`; every other length
works. The sweep:

| length | result |
| ---: | --- |
| 1,023 / 1,024 / 1,025 | OK |
| 2,047 / 2,048 | OK |
| 2,049 (chunk+1) | **exit 1** |
| 4,097 (= 2*chunk+1) | **exit 1** |
| 4,098..4,136 (tails 2..40) | **exit 1** |
| 8,193 (= 4*chunk+1) | **exit 1** |

So the trigger is not "one token": any tail of 1..1,024 tokens on a prompt
longer than one chunk. At a 1,025..2,047-token tail the ffn shapes are wide
enough to keep `blocks >= 192`, so the split is not selected and the stale
one-value buffer is never touched.

### Cause

`Chunk::new` sized the split scratch from the **chunk**:

```rust
let sk = if tokens <= 1024 { tokens * wide } else { 1 };
```

but `prefill_should_split` is evaluated per **tile** in `gemm_half`. For
8,193 = 4*2,048 + 1 the last tile is one token; at `m = 17,408`,
`blocks = ceil(17408/128) * 1 = 136`, which is inside `[32, 192)`, so the
last tile runs `prefill_q4_k_w2h_sk` and wants `1 * 17408` values while the
buffer holds one.

## 2. The fix

A new helper in `crates/hipml-kernels/src/launch/device/prefill_launch.rs`:

```rust
pub fn prefill_split_scratch_cap(max_tokens: usize, max_rows: usize) -> usize
```

It is the allocation side of `prefill_should_split`. A `t`-token tile can
select the split only while

```
ceil(m / 128) * ceil(t / 256) < 3 * 64
```

so the widest shape it can select at that length is
`128 * ((3*64 - 1) / ceil(t/256))`, and the scratch must hold the maximum of
`t * m` over every `t <= chunk`. `Chunk::new` and `RowScratch::new` both use
this one function; the launch check (`scratch.len() < tokens * m`) remains as
an assertion.

**Why it is sufficient.** At launch, `m <= wide = max(n_embd, n_ff, ssm
inner)` for every projection that uses `sk` (the ffn gate/up/down), and the
predicate's `blocks < 192` implies `m <= 128 * floor(191 / ceil(t/256))`.
Hence every selectable tile satisfies `t*m <= t*min(wide, bound)`, which is
exactly what the helper maximises. The two sides cannot disagree again
without disagreeing with the same predicate.

### Cost

For the shipped model (`wide = 17,408`) the helper allocates:

| chunk capacity | scratch |
| ---: | ---: |
| 256 | 17.0 MiB |
| 512 | 23.75 MiB |
| 1,024 | 23.75 MiB |
| 2,048 (default) | 23.75 MiB |
| any larger chunk | <= 23.9 MiB |

The old rule allocated 34 MiB at 512, 68 MiB at 1,024, and **4 bytes** above
1,024. So the long-prompt cost is a one-time +23.75 MiB; short chunks actually
shrink. Measured `gpu-bench` chunk scratch at 8K and 100K:

```
              before     after     delta
8K/100K chunk 1667.2 MiB 1691.0 MiB +23.8 MiB
depth 0        (no chunk allocated)      0
```

## 3. The permanent gate

`hipml splitk-gate --gguf PATH [--chunk 2048 --tails 40]` runs the same ids
twice on one engine: split enabled, then `HIPML_SPLITK=0`. It covers
`chunk-1`, `chunk`, `chunk+1`, `2*chunk+1`, `4*chunk+1`, and every tail
`1..40` of a `2*chunk` prompt (44 lengths at the default chunk). Ids must be
identical. Logits are bounded by the split's documented arithmetic contract
(deterministic, not bit-identical):

* deterministic synthetic prompt: `max |dlogit| <= 0.05`;
* caller `--ids-file` fixture: ids must match and `max |dlogit| <= 16`, because
  a real-token recurrence can amplify last-bit ffn differences.

Measured on the fixed tree:

```
synthetic: PASS 44/44, worst |dlogit| 0.0112 <= 0.05
fixture:   PASS 44/44, worst |dlogit| 9.3098 <= 16, ids identical
```

The gate fails on the old tree at the first crashing length, so it would have
caught this before release.

## 4. Attention split scratch: not the same defect

`apart`/`apart_ml` are allocated from the **maximum** splits and query slots:

```
apart     = splits * ceil(cap/32)*32 * n_head * head_dim
apart_ml  = splits * ceil(cap/32)*32 * n_head * 2
```

At call time the kernel uses `qslots = ceil(n_tok/32)*32` for the tile and
`split_count(c.attn_splits, pos0)`, so the live requirement is
`split_count <= attn_splits` and `qslots <= allocation qslots`. Both hold for
every tile because `n_tok <= cap`. At 8,193 the last tile is one token at
`pos0 = 8192`: it asks for `8 * 32 * n_head * head_dim`, while the buffer was
sized for `8 * 2048 * ...`. The buffer is over-sized, not under-sized. The
8,193 gate case exercises exactly this path and passes.

## 5. Re-measured prefill

`gpu-bench --gguf ... --prefill N` on the fixed tree:

| prompt | KV | time | tok/s | last id |
| ---: | --- | ---: | ---: | ---: |
| 8,192 | f32 | 6.61 s | 1,240 | 292 |
| 8,192 | q8 | 6.61 s | 1,240 | 292 |
| 8,193 | q8 | 6.72 s | 1,219 | 852 |
| 32,768 | q8 | 28.62 s | 1,145 | 868 |
| 100,000 | q8 | 107.94 s | 926 | 100 |

No regression: 8K 6.61 s (<= 6.7), 100K 107.94 s (<= 108.5). The 8,193
case that used to exit 1 now completes in 6.72 s.

## 7. What is unverified

* Peak VRAM was not sampled with the WDDM counter; the +23.8 MiB is the
  measured `chunk_bytes` delta, and every other chunk buffer is unchanged.
* Only the Qwen3.8-27B ffn shapes were measured; larger `n_ff` would raise the
  helper's bound, still capped near 24 MiB by the predicate's 192-block limit.
* Chunks larger than 2,048 were not benchmarked; the helper's bound is
  asymptotic there but the prefills were not run.
* Natural-prompt logit drift is not tightly bounded: ids match 44/44 on the
  fixture, but the recurrence can amplify last-bit differences to ~9 logits.
  The split remains deterministic-but-not-bit-identical, as documented.
* Attention split scratch was exercised at 8,193 with the default 8 splits;
  other `HIPML_ATTN_SPLITS` values were not swept.
